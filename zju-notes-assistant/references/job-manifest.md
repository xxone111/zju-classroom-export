# Job Manifest Handoff

Use this when a local web login/export helper created `zju-notes-assistant.job.json`, or when the user asks to continue after exporting transcripts from the helper page.

The manifest links the fast local export UI with later AI/skill workflows. Treat it as the source of exported transcript paths. The helper page should not decide the downstream workflow; ask the user what to do next unless their current request already states it.

The normal user handoff is a sentence generated by the helper, not a manifest path. For example:

```text
请使用 zju-notes-assistant 读取最近一次导出的课堂录音（课程名，共 N 节），并按我的默认笔记方式继续处理。
```

When this request is received, load `~/.zju-notes-assistant/latest-job.json` automatically. Do not ask the user where the JSON file is unless that default file is missing or invalid.

## Manifest Shape

```json
{
  "schema": "zju-notes-assistant.job.v1",
  "created_at": "2026-09-14T12:00:00.000Z",
  "output_mode": "local_path",
  "output_dir": "~/Downloads/zju-classroom-transcripts",
  "next_workflow": "ask",
  "items": [
    {
      "course_name": "中级财务会计",
      "teacher": "教师",
      "date": "2026-05-12",
      "section": "第7-8节",
      "course_id": "123",
      "sub_id": "456",
      "transcript_md": "/path/to/transcript.md",
      "transcript_filename": "中级财务会计_语音识别原文.md",
      "transcript_lines": 1800,
      "course_folder": "/path/to/output/中级财务会计",
      "next_workflow": "ask"
    }
  ]
}
```

## How To Continue

1. Locate the manifest.
   - Prefer a user-provided path.
   - Otherwise first check `~/.zju-notes-assistant/latest-job.json`.
   - Then look in the transcript output folder for `zju-notes-assistant.job.json`.
   - Current helpers should record absolute transcript paths when using the native macOS path picker.
   - If an older helper manifest contains only filenames, ask for the selected folder path.
2. Validate every `transcript_md`.
   - If `transcript_md` is absolute or starts with `~`, expand and check it.
   - If it is a filename only, resolve it relative to the manifest's folder or `output_dir`.
3. Determine workflow:
   - If the user's current request already says what to do, follow that request.
   - Otherwise read `default_note_workflow` from config. `chapter_notes` means A 章节笔记; `pdf_annotation` means B 课件精注; `custom` means C 自定义模板 using `style_reference_path`.
   - If there is no configured default, ask whether to stop after export, annotate PDF and make a classroom summary, or generate chapter notes.
   - For PDF annotation, read `pdf-integration.md`.
   - For chapter notes, read `chapter-notes.md`.
4. Determine courseware/PDF source:
   - Prefer the manifest item's `course_folder`; all export types for that course should share this folder.
   - If the user provided a PDF path or course folder in the conversation, validate it.
   - Otherwise use `vault_root`, course name, date, section words, and PDF content matching. Do not depend on frontmatter.
   - Ask for a PDF path or course folder when automatic matching is ambiguous.
5. If multiple items are in the manifest, process them one at a time and report progress.
6. Write generated summaries, chapter notes, and other downstream artifacts into the same `course_folder` by default. Copy into a separate note vault only when the user explicitly requests that second copy.

## User Prompts

If data is missing, ask narrowly:

- For PDF annotation: ask for a PDF path or course folder when matching is ambiguous. Remind the user to convert PPT/PPTX to PDF first.
- For chapter notes: ask for the course folder or PDF path if automatic matching is low-confidence.
- If paths are only filenames, ask for the selected output folder path.

## Safety

- Do not modify PDFs or existing notes until the transcript and PDF/course folder are validated.
- Do not permanently delete raw transcripts or manifests.
- Preserve both `zju-notes-assistant.job.json` in the output folder and `~/.zju-notes-assistant/latest-job.json`; they are reproducibility records for the export.
